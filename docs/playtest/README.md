# Набор для плейтестов (Stage 360)

Для владельца: как провести три–пять сессий без подсказок с живыми людьми на развёрнутой сборке,
по-русски, и как записать результат. Задача сессий — ответить на один вопрос:
**взаимодействовали ли участники с миром — или искали, куда нажать?**
(`EXECUTION_PLAN.md`, Stage 360; `work-orders/OPUS_STAGE_360.md`).

Прогон ИИ-участников (`reports/STAGE_360_PLAYTESTS.md`) — только фильтр очевидных шероховатостей.
Приёмкой он не является; приёмка — только эти сессии.

| [`setup-ru.md`](setup-ru.md)                               | ведущему (владельцу)        | развернуть сборку, кампанию и ссылки; проверить до прихода людей              |

## Формат одной сессии

- 30–45 минут, по-русски, на развёрнутой сборке (`deploy/RUNBOOK.md`), на кампании
  «Пропавший караван» (Russian Ravenford).
- Состав: DM и один игрок. В альфе у кампании один персонаж игрока (Эловен Старвиспер), поэтому
  «один–три игрока» из плана здесь означает одного; второй человек может только наблюдать.
- Ведущий не помогает. Если участник застрял дольше трёх минут и просит помощи, наблюдатель
  записывает момент и даёт **одну** нейтральную подсказку из `observer-ru.md`; каждая подсказка —
  отдельная строка в записи.
- Каждая сессия — на новой кампании (`deploy/scripts/review-campaign.sh` на чистой базе или
  отдельный стек), чтобы участник не увидел следов предыдущей.

## После сессий

1. Записи сессий кладутся в `reports/evidence/stage-360/` (без токенов и без ссылок-приглашений;
   имена участников — только инициалы или «Участник A»).
2. Сводка и находки — в `reports/STAGE_360_PLAYTESTS.md`, раздел «Сессии с людьми».
3. Владелец решает по каждой находке; блокирующие исправляются с регрессионными тестами, после
   исправления — ещё одна сессия.
4. Только потом — выпуск v0.1: полная проверка на финальной ревизии, тег, запись в
   `reports/STAGE_250_RELEASE.md` (подготовка — `docs/RELEASE_CANDIDATE.md`).
