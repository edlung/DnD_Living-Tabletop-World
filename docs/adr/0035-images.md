# 0035. Images: OpenAI through OpenRouter in play, a curated set, purposes, PostgreSQL storage

- Status: Accepted (owner product decisions Q6 of 2026-10-05 and 2026-10-15; technical design by
  the session)
- Date: 2026-10-15
- Stage: 330
- Decision type: product (provider, spending ceiling, curated set) and technical.
- Owner approval: Q6 — OpenAI image models only, accessed through OpenRouter (2026-10-05); "Набор —
  подписка, в игре — OpenRouter до $5" (2026-10-15): the curated Ravenford set is generated through
  Codex CLI on the owner's ChatGPT subscription and imported as DM-approved; in-play generation uses
  OpenRouter with a $5 ceiling. All art is GPT-made and follows the owner's concepts (ADR 0034).
  Full design: `docs/STAGE_330_DESIGN.md`.

## Context

The image port (ADR 0022) had only a placeholder generator. Players saw neutral fallbacks. Identity
must hold across variants; spending must be bounded; images must reach players only after DM
approval; storage and backup must be decided for production.

## Decisions

1. **Generators behind the port.** `openrouter-openai` (in play: OpenAI image model through
   OpenRouter's chat completions with image output; fixed style prompt; derived variants attach the
   approved canonical reference; output validated and re-encoded to WebP ≤ 1.5 MB); `placeholder`
   (tests, offline); `curated` (seed import only).
2. **Ceiling.** A durable image ledger reserves a worst-case amount before any provider call and
   settles to the reported cost; the ceiling is set only by the operator CLI with an authorization
   source; no stored ceiling or zero means no call. Initial ceiling: $5.
3. **Curated set.** Generated once in the concepts' style, committed as WebP with a manifest
   (prompt, references, hashes), imported through real commands and approved as DM on a fresh
   install; never regenerated by an install.
4. **Purposes.** Assets carry `purpose`: `image` (chosen by ADR 0023 tags as before), `figure` (a
   character's tabletop figure) and `battle-map` (a place's top-down map under the encounter grid).
   Additive fields in `PlayerAssetView` and `EntityPresentation`; lineage, approval and visibility
   unchanged.
5. **Storage.** Image bytes stay in PostgreSQL (`ltw_asset_contents`, ≤ 2 MB each): one store,
   transactional with lineage, included in Stage 350's dumps. Trigger to move to object storage:
   a dump larger than 2 GB or taking longer than 5 minutes.
6. **Privacy.** A request is built from the entity's description; DM-only notes enter only when the
   DM types them into the request. No image reaches a player before approval; refusals, timeouts and
   provider errors leave the neutral fallback.

## Consequences

- Identity drift is measured per image (`reports/STAGE_330_IDENTITY.md`); drifted variants are
  regenerated or reported.
- The DM gets approval controls (approve, discard, generate again, replace) in the client.
- Image routes are Gate 06 surfaces (cost, visibility, prompt injection through descriptions).
