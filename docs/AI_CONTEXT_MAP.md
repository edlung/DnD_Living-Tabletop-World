# AI Context Map

Product/architecture documents are at the repository root. Paths below are relative to that root. Stages 0 (repository foundation), 10 (World Kernel), 20 (Knowledge Boundary), 30 (Memory), 40 (Rules), 50 (Context Engine), 60 (Investigation), 70 (Contradictions), 80 (Combat), 90 (Reactions), 100 (AI Gateway), 110 (AI Authoring), 120 (Continuity Engine), 130 (NPC Intelligence), 140 (AI Relevance), 150 (Asset Identity), 160 (World Visual State), 170 (Chronicle), 180 (Ravenford Integration), 200 (UX Foundation), 210 (World as Interface), 220 (Combat UX), and 230 (DM Authoring UX), 240 (DM session tools), 310 (live session: part A signal and presence, parts B and C DM table tools), 320 (visual language: part A tokens, fonts, the GPT UI kit in the client, shell, scene, conversation, details, sign-in; part B the battlefield; part C the Chronicle as a book, the flashback as a scene, the DM's tools, the accessibility and responsive pass), 340 (production sign-in: part A the server, part B the browser), 330 (images: part A server, domain and contracts; part B the DM's image controls, figures and battle maps in the client), and 350 (deployment: Compose behind Caddy, readiness, backups, restore drill, runbook; the network trust boundary, the review campaign, sign-in journeys on the deployment; the full product: curated pictures through the proxy, image spending, browser journeys against the deployment) have added the code/tooling entry points in the second table; each later stage keeps them current. Read the nearest `AGENTS.md`, then only the entries needed for the task.
