[G06-client-01] Semantic entity IDs of unidentified combatants leak to the player.
 - DM placed goblin-raider-1/2 and goblin-shaman at old-trade-road and StartCombat with Elowen.
 - Player (CHARACTER:elowen-starwhisper) GET /campaigns/ravenford/encounter and /locations/old-trade-road/scene
   return combatants with entity.name=null (correctly unidentified) BUT entity.entityId="goblin-shaman",
   "goblin-raider-1","goblin-raider-2" in combatants[], order[], currentCombatantId.
 - Confirmed the player's OWN BROWSER JS receives them: in-page fetch(encounter) -> 200, body includes "goblin-shaman".
 - Client UI hides them: rendered DOM contains no goblin-raider/goblin-shaman in text/attributes/aria (only the
   legitimate party knowledge id "goblin-hypothesis"). So the leak is the network projection, reachable via devtools.
 - Evidence: net/player-encounter-leaks-goblin-ids.json, net/player-scene-leaks-goblin-ids-and-equipment.json,
   browser-dom.html, and in-browser fetch log (this file).
 - Violated: ADR 0008 §50 (secret-identity entity must get an OPAQUE id, not referenced by non-DM records);
   apps/web/AGENTS.md:147-150 ("never its ID"); ADR 0027 (unidentified stays unidentified).
