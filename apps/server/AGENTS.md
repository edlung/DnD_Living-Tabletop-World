# Server (`@ltw/server`)

Composition root of the modular monolith and the only workspace package allowed to perform I/O (`docs/adr/0004-module-boundaries.md`).

Live AI (Stage 300, remediation in progress): start with ADR 0032 (amendment 2026-10-11),
`src/ai/gateway.ts` and `src/ai/accounting/AGENTS.md`. Through remediation checkpoint B1 composition
is local-only (no remote adapter is built, no key revealed); the durable PostgreSQL accounting store
exists but no use case calls it until B2. Raw adapters (`prepare`/`dispatch`, `src/ai/raw-provider.ts`)
are reached only by their unit tests with injected `fetch`; routers for runtime and evaluation come
only from `src/ai/composition.ts` (`composeRouter`, identity-checked). Follow
`docs/PROJECT_WORKFLOW.md` and the approved remediation scope. Never run paid evaluation without
explicit text-provider ceilings; OpenRouter's $20 image-key limit is a separate authorization.

- Later domain modules go under `src/<feature>/`, each cohesive and imported directly; keep orchestration thin.
- Stage 200 reads: `src/http/routes/session-routes.ts` returns authenticated caller identity and current perspective choices; `character-routes.ts` returns a whitelisted sheet only to DM perspective or its own CHARACTER holder. Boundary tests: `src/http/session-routes.test.ts`, `character-routes.test.ts`. A DM preview never inherits DM sheet access.
- Stage 210 `src/http/routes/surroundings-routes.ts` enumerates the resolved character's perceived current/nearby locations through `@ltw/context`; non-character perspectives are refused, and unknown names stay null. Boundary/reload journey: `src/http/surroundings-routes.test.ts`.
- Canonical mutation stays behind the World Engine boundary (`ARCHITECTURE_INVARIANTS.md` #1–2). Platform code never decides domain legality.
- `*.integration.test.ts` needs PostgreSQL (`pnpm db:up`); everything else is a unit test. Integration tests create a throwaway database each via `src/testing/throwaway-database.ts`.
- Canonical kernel state is never served over HTTP. Player-facing reads go through the knowledge perspectives (`resolvePerspective` and the queries in `@ltw/domain`); never add a route that returns canonical objects.
- HTTP tests use `src/testing/ravenford-app.ts` (seeded in-memory engine, real persona tokens, `testAiGateway` with the local provider and in-memory traces, `testAuthoring` with in-memory proposals, `testAssets` with in-memory contents, and `post`) and the shared spec `fixtures/ravenford/knowledge-boundary.json`.
