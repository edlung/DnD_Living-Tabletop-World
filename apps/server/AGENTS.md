# Server (`@ltw/server`)

Stage 380 workshop access: `src/workshop/AGENTS.md` is the entry for independent
owner credentials and private draft containers. Production composition wires it
only beside invitation-mode sign-in; its HttpOnly cookie never authenticates a
campaign. Contracts: `packages/contracts/src/workshop/access.ts`; operator:
`pnpm workshop:operator`. Owner disposition: ADR 0038 through
`reviews/STAGE_370_OWNER_DISPOSITION_2026-10-30.json`. Unlimited monetary policy is
explicitly recorded in `src/ai/accounting/monetary-policy.ts`; never infer a grant
from a missing finite ceiling or an environment flag.

Stage 400 campaign preparation: `src/workshop/generation/AGENTS.md` covers durable
jobs and artifacts; `src/ai/preparation-gateway.ts` binds the same admitted provider
to a genuine workshop preparation session. Migration0018 preserves campaign
accounting while adding workshop subjects. Explicit preparation owner grants and
account UNLIMITED policy remain necessary. No local generator substitutes for a
missing route. Production composition starts the bounded preparation worker only
beside invitation-mode workshop auth.

Stage420 scoped visual preview: `src/workshop/preview/AGENTS.md`; private images:
`src/workshop/images/AGENTS.md`. Main starts a separate fenced draft image worker
beside invitation auth. It uses existing image settings and explicit stored image
UNLIMITED policy, without calling the canonical asset worker. Migrations0019/0020
require an aware recovery build; see `deploy/RUNBOOK.md`§3.

Composition root of the modular monolith and the only workspace package allowed to perform I/O (`docs/adr/0004-module-boundaries.md`).

Live AI (Stage 300, remediation in progress): start with ADR 0032 (amendments 2026-10-11 and later, C last),
`src/ai/gateway.ts` and `src/ai/accounting/AGENTS.md`. Since checkpoint B2 every AI request runs
through the PostgreSQL request journal (`src/ai/journal.ts`), and a remote provider exists only as
an admitted wrapper (`src/ai/admitted-provider.ts`) built by `gateway.ts` with a selected stored
approval, the accounting store and a verified catalog entry (`src/ai/catalog.ts`, `pricing.ts`).
The verified catalog has exactly one entry since checkpoint C, `anthropic:claude-sonnet-5-5`
(`src/ai/catalog-sonnet-5-5.ts`, from the owner-authorized verification record of 2026-10-12); every
other model is refused at startup. A Sonnet route sends only with its key, a selected stored approval
and an eligible session that admission accepts; per-capability effort and `max_tokens` are trusted code
(`src/ai/request-settings.ts`), and a body outside the adapter's own shape is refused before
reservation (`src/ai/request-shape.ts`). Runtime relevance stays deterministic (owner decisions 6). Every Vitest project runs with a global `fetch` trap
(`tests/setup/no-network.ts`): tests inject `fetch`. Live evaluation (`src/testing/eval/`, `pnpm eval:ai
--live`) needs a stored approval and an operator-registered run; see `src/testing/eval/eval-live.ts`.
Raw adapters (`prepare`/`dispatch`, `src/ai/raw-provider.ts`) are imported only by `gateway.ts` and tests (`tests/architecture/raw-adapter-imports.test.ts`); routers
come only from `src/ai/composition.ts` (`composeRouter`, identity-checked). The DM's accounting
diagnostic is `GET …/ai/accounting/:traceId` (`src/ai/diagnostics.ts`). Follow
`docs/PROJECT_WORKFLOW.md` and the approved remediation scope. Never run paid evaluation without
explicit text-provider ceilings; OpenRouter's $20 image-key limit is a separate authorization.

- Later domain modules go under `src/<feature>/`, each cohesive and imported directly; keep orchestration thin.
- Stage 200 reads: `src/http/routes/session-routes.ts` returns authenticated caller identity and current perspective choices; `character-routes.ts` returns a whitelisted sheet only to DM perspective or its own CHARACTER holder. Boundary tests: `src/http/session-routes.test.ts`, `character-routes.test.ts`. A DM preview never inherits DM sheet access.
- Stage 210 `src/http/routes/surroundings-routes.ts` enumerates the resolved character's perceived current/nearby locations through `@ltw/context`; non-character perspectives are refused, and unknown names stay null. Boundary/reload journey: `src/http/surroundings-routes.test.ts`.
- Canonical mutation stays behind the World Engine boundary (`ARCHITECTURE_INVARIANTS.md` #1–2). Platform code never decides domain legality.
- `*.integration.test.ts` needs PostgreSQL (`pnpm db:up`); everything else is a unit test. Integration tests create a throwaway database each via `src/testing/throwaway-database.ts`.
- Canonical kernel state is never served over HTTP. Player-facing reads go through the knowledge perspectives (`resolvePerspective` and the queries in `@ltw/domain`); never add a route that returns canonical objects.
- HTTP tests use `src/testing/ravenford-app.ts` (seeded in-memory engine, real persona tokens, `testAiGateway` with the local provider and in-memory traces, `testAuthoring` with in-memory proposals, `testAssets` with in-memory contents, and `post`) and the shared spec `fixtures/ravenford/knowledge-boundary.json`.
