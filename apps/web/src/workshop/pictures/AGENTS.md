# Owner draft pictures

- `panel.tsx` reads bounded job/candidate pages for one stored revision. Selection
  and generation are explicit separate actions. No candidate enters preview implicitly.
- `form.tsx` displays the exact selected purpose's appearance/style brief. Send only
  the note and public slot/CAS request fields; never compose narrative owner secrets.
- Stage420 slots are reference `image` with null label and derived `figure` /
  `battle-map` with matching labels. Derived purposes require a chosen raster reference.
- `actions.ts` retains the original uncertain payload/nonce across object navigation;
  a same-owner409 preserves conflict state. Changed/revoked ownership releases the
  shared client and removes the private branch. Unknown dispatch is never retried by a loop.
- Candidate/selected bytes use a revision-bound reader, fresh image consumers per
  manifest and released object URLs. Character preview never mounts this subtree.
- `cards.tsx` presents selection and staleness; `jobs.tsx` presents honest job states.
  No route/policy is an unavailable state, never a local generated picture fallback.
- Styles/dictionary: `styles/workshop-pictures.css`, `i18n/ru-workshop-preview.ts`.
