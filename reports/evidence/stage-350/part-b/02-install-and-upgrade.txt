### Finding (2026-10-16T01:07Z): the attempt above failed (the grep at the end of that command line hid deploy.sh's exit status; every later command line sets pipefail)
With --force-recreate, Compose 5.1.4 stopped the proxy and removed the edge network while the
server (on part A's layout) still used it: "network ltw-stage350b_edge has active endpoints".
Without --force-recreate (a trial run before this transcript) Compose recreated the networks but
only restarted PostgreSQL, which came back on the new data network without its service name, so
the server's migrations failed with "getaddrinfo ENOTFOUND postgres". deploy.sh now takes the
stack down first when the resolved networks differ from the last deploy's digest (`compose down
--remove-orphans`: containers and networks only; volumes, the backup directory and the database
stay), then starts it. The images are unchanged; only the host script changed. State now: the
proxy stopped, the other services still on part A's networks, deploy/.env already names
8b362b15ec68 with 333a8791b1e8 as the previous tag.
